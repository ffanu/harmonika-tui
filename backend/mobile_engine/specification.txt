================================================================================
  EXPO vs REACT NATIVE CLI vs FLUTTER
================================================================================

EXPO (Managed):
  + Setup cepat (5 menit)
  + EAS Build & Submit (no Xcode needed)
  + OTA updates built-in
  + Ideal untuk startup & MVP
  - Bundle size lebih besar
  - Beberapa native module tidak support

REACT NATATIVE CLI (Bare):
  + Full control native code
  + Smaller bundle size
  + Native module tidak terbatas
  - Setup lebih rumit
  - Butuh Xcode + Android Studio
  - Manual build & deploy

FLUTTER:
  + Single codebase (Dart)
  + Performance baik (compiled to native)
  + Widget system konsisten
  + Hot reload
  - Bundle size besar (5-20MB minimum)
  - Dart (kurang populer dari JS/TS)
  - Native integration lebih rumit


================================================================================
  ANDROID vs iOS DEPLOYMENT DIFFERENCES
================================================================================

ANDROID (Google Play):
  - Build: AAB (App Bundle)
  - Sign: keystore (.jks)
  - Review: 1-3 hari (auto + manual)
  - Rollout: staged (1% → 100%)
  - Update: 1-3 hari sampai user
  - Cost: $25 (one-time)
  - Test: Internal, Closed, Open testing

IOS (App Store):
  - Build: IPA
  - Sign: provisioning profile + certificate
  - Review: 24-48 jam (manual)
  - Rollout: phased (1% → 100% dalam 7 hari)
  - Update: 24-48 jam sampai user
  - Cost: $99/tahun
  - Test: TestFlight (internal + external)
  - BUTUH: macOS untuk build (Xcode)

================================================================================
  ANTI-HALLUCINATION & SAFETY (MOBILE)
================================================================================

1. SPEC-DRIVEN
   - Tidak nambah fitur yang tidak di-spec
   - Kalau ada ambigu, tanya user
   - Tidak assume requirements

2. TEST BEFORE DEPLOY
   - Wajib unit test
   - Wajib E2E test di emulator
   - Wajib test di real device (device farm)

3. STORE POLICY COMPLIANCE
   - Play Store Policy (data safety, target SDK)
   - App Store Review Guidelines (Human Interface)
   - GDPR / CCPA consent dialog
   - ATT (App Tracking Transparency) untuk iOS

4. SECRETS MANAGEMENT
   - API keys di environment variables
   - Tidak hardcode secrets di code
   - Keystore & provisioning profile di secure storage

5. SIGNING SAFETY
   - Backup keystore & passwords
   - Backup provisioning profile & certificates
   - Tidak commit keystore ke git

6. ROLLOUT SAFETY
   - Staged rollout (10% → 50% → 100%)
   - Monitor crash rate post-deploy
   - Ready untuk rollback / hotfix

7. PERMISSION JUSTIFICATION
   - Request permission only when needed
   - Jelaskan kenapa butuh permission
   - Graceful fallback jika denied
