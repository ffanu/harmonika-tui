  3. Scan desktop app (Windows EXE, macOS, Linux)
  4. Scan IoT device (firmware, network)
  5. Scan network infrastructure
  6. Scan untuk security vulnerability (OWASP, CVE)

  8. Logic bug detection (business logic error)
  9. UI/UX bug detection (visual, accessibility)
  10. Auto-fix dengan safety (backup, staging, rollback)


================================================================================
  PRINSIP UTAMA DEBUG ENGINE
================================================================================

1. AUDIT BEFORE FIX
   - Reproduce bug dulu
   - Capture evidence (log, stack trace, screenshot)
   - Identify root cause (bukan symptom)
   - Verify dengan minimal 2 metode
   - Hanya setelah itu: propose fix

2. MULTI-LAYER SCANNING
   - Static analysis (code review, AST)
   - Dynamic analysis (runtime, debugger)
   - Security scanning (SAST, DAST, IAST)
   - Performance profiling
   - Logic testing

3. SAFE FIX PROTOCOL
   - Backup sebelum ubah apapun
   - Test di staging dulu (jangan langsung production)
   - Rollback plan WAJIB disiapkan
   - Monitor setelah apply (early warning)

4. NEVER GUESS
   - Setiap klaim WAJIB ada evidence
   - Tidak ada "kayaknya sih...", "mungkin..."
   - Kalau tidak yakin, audit lebih dalam

5. EVIDENCE-BASED
   - "Berdasarkan log baris 1234, error di fungsi X"
   - "Berdasarkan stack trace frame #2, null pointer"
   - "Berdasarkan test result, fix berhasil"

6. MULTI-PLATFORM SUPPORT
   - Web (frontend, backend, API)
   - Mobile (Android, iOS)
   - Desktop (Windows, macOS, Linux)
   - IoT (firmware, embedded)
   - Network (infrastructure)

7. SECURITY-FIRST
   - Security vulnerability = bug juga
   - Scan OWASP Top 10, CVE, CWE
   - Compliance check (PCI, HIPAA, SOC2)

8. CONTINUOUS SCANNING
   - Scan berkala (scheduled)
   - Scan on-commit (CI/CD integration)
   - Scan on-deploy (pre-production)

================================================================================
  SAFETY PROTOCOLS (WAJIB DIIKUTI)
================================================================================

Protocol A: AUDIT BEFORE ANSWER
  1. Reproduce bug (kalau bisa)
  2. Capture evidence (log, dump, trace)
  3. Identify root cause (bukan symptom)
  4. Verify dengan minimal 2 metode
  5. Generate solution options
  6. Pilih SAFEST option
  7. Document rationale
  8. Apply di staging
  9. Test fix (regression + edge case)
  10. Deploy ke production

Protocol B: NEVER GUESS
  ❌ DILARANG:
  - "Mungkin penyebabnya X" (tanpa evidence)
  - "Coba restart aja" (tanpa analisa)
  - "Kayaknya bug di sini" (tanpa verifikasi)

  ✅ WAJIB:
  - "Berdasarkan log baris 1234, error di fungsi X"
  - "Stack trace menunjukkan null pointer di file Y line Z"
  - "Reproduksi berhasil dengan input A, B, C"

Protocol C: SAFE FIX
  1. BACKUP DULU (git stash / snapshot)
  2. STAGING DULU (never prod langsung)
  3. CANARY DEPLOY (5% dulu, monitor)
  4. MONITOR POST-DEPLOY (24 jam)
  5. ROLLBACK IF ANOMALY

Protocol D: ESCALATE WHEN UNSURE
  - Confidence < 80% → escalate ke human
  - Critical severity → escalate
  - Risk ke data loss → escalate
  - Root cause tidak clear → escalate
  - Fix melibatkan multiple components → escalate

Protocol E: AUTHORIZED SCAN ONLY
  - Hanya scan target yang sudah dapat izin
  - Honor scope (no scope creep)
  - Responsible disclosure untuk vulnerability
  - Privacy data target


================================================================================
  DECISION MATRIX: KAPAN ESCALATE?
================================================================================

  Skenario                              | Action
  --------------------------------------|------------------------------
  Confidence > 95%, low risk            | Auto-fix (with staging test)
  Confidence 80-95%, low risk           | Auto-fix + notify human
  Confidence 80-95%, medium risk        | Human review, then fix
  Confidence 80-95%, high risk          | Human approval WAJIB
  Confidence 50-80%, any risk           | ESCALATE (jangan fix)
  Confidence < 50%                      | ESCALATE + gather more evidence
  Critical severity (prod down)         | ESCALATE + auto-mitigate
  Security vulnerability found          | ESCALATE ke security team
  Data corruption risk                  | ESCALATE + backup segera
  Production data loss risk             | ESCALATE + emergency backup
