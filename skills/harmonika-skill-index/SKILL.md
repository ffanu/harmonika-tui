description: Discover exact Harmonika backend capabilities, audit consolidated indexes, and run bounded defensive evidence analyses or isolated HTML browser checks.

Use automatically when a task concerns system capability/readiness, defensive
source/header/binary analysis, or a source-index gap. First call
`harmonika catalog capabilities`, then `harmonika catalog list --status available`.
Inspect the selected exact ID's schema with `harmonika catalog inspect ID`.
Send JSON stdin via `harmonika catalog invoke ID`; never put key/password in argv.

Existing coding/builder/legal/telco operations preserve their original context,
auth scope, idempotency and approval. Supply the relevant workspace/project ID;
use a stable --idempotency-key UUID for write retries, then follow the original job status/events/approve/stop endpoint returned by that engine.
Do not fabricate aliases from similar names or silently read another tenant's case.

Master v1 has1200unique A–Z IDs, not1507. Registration is not readiness. Missing or
restricted handlers are not successful operations. Cloud/proprietary connectors
and real customer/company information require authorized, configured sources.

Defensive analyzers inspect supplied evidence only. Heuristics are signals, not
proof that a user is a bot, a payment is genuine, or a system/file is malware-free.
No autonomous credential attacks, session theft, persistence/cover-tracks or bypass.

`workflow.browser` uses supplied HTML inside an ephemeral, networkless, software
Chromium container. It does not control the user's billing/CS/browser profiles or
visit arbitrary URLs. Screenshot hashes are evidence of capture, not image URLs.
